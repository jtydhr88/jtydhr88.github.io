如何使用AI逆向一款游戏—UE篇

Terry · 2026-10-06

其实写上一篇《如何使用AI逆向一款游戏》的时候，同步还在逆向一款UE游戏。

从技术难度上讲，UE的游戏难度要比Unity高一些。

不过同样，因为我在手工的时代做过一些，所以方向上我可以把AI引入到我想让它做的方向去。

本人不会透露这款游戏的任何信息和截图。

鉴于上一篇的经验，不要过来问我问题，包括但不限于：

  • “网游服务器的数据怎么破解？”
  • “能不能破解D版？”
  • “能不能逆向xx？”
  • “怎么引导AI让它做逆向？”

更讨厌的语气是“你去试试xx能不能行”“这样做xx的意义xxx”，这种一律拉黑删除。

算上之前的问题：

  • “这是什么游戏？”
  • “能不能用在其他游戏上？”
  • “我的AI为什么不行？”
  • “帮我也搞下呗，付费也行”

本人概不负责相关答疑，任何相关问题回复一律是：

你去自己试试。

Part 00

环境

  • 游戏：某手机游戏安卓版
  • 运行环境：某安卓模拟器
  • 游戏引擎：Unreal Engine 定制版
  • AI：Claude Opus 5.5
  • 操作系统：Windows 10

这次比上次多用了不少东西，基本都是 AI 自己装或是自己编译的：

  • .NET 10 SDK（解包库要求，之前系统里只有 9）
  • Ghidra（反编译）
  • unicorn（CPU 模拟器）
  • SPIRV-Cross（自己用 MSVC 编的）
  • Vulkan（拿显卡直接跑游戏原版 shader 做核对）
  • 无界面 Chrome（自动截图、回归测试）
Part 01

提取资源

和上次一样，我只给了模拟器，剩下的它自己来。

  • 模拟器的 adb 可以直接 root，游戏文件的属主是应用自己、权限 660，普通 shell 读不了，root 之后就能读；
  • 首包、进游戏后补下的延迟包、热更补丁，一共四百多个文件、四十来个 G，它在设备端打 tar 包，流式传回来再解开，大概 25 分钟；
  • 拉完自己做了一遍完整性校验，顺带发现热更配置和日志也是加密的（每行一个固定前缀 + base64）。

同时我电脑上本来就装着这个游戏的 PC 版，它也原地挂上来做对照。

Part 02

解包资源

UE5 的资源是 IoStore（.utoc / .ucas）加 .pak，一半的容器是加密的，压缩用 Oodle。

  • 密钥分两种：一把主密钥，加上服务器下发的一堆动态密钥。社区里有公开整理的密钥和类型映射文件，它直接用上了；
  • 它写了一个 C# 命令行工具包住开源解包库，后面几乎所有导出都走它：列目录、导 JSON、导原始网格、导贴图、导 shader、导动画……命令一路加到了四十多个；
  • 手机包有个坑：首包里藏在安装包的一个“伪装成 png 的 zip”里，里面有全局容器，不先挂上它，手机包的资源一个都读不了；
  • 同一个资源会因为补丁在多个容器里出现好几份，一开始它随便取了一份，后来专门逆向了游戏的容器挂载优先级，按游戏的规则选，重新导了一遍，审计出来 1600 多个过期文件全部换掉。
Part 03

资源映射

套路和上次差不多，但这次的格式完全不同。

  • 配置表是一千四百多张二进制表，某开源配置框架的格式，没有字段名，整数是大端变长编码。它照着格式按索引切记录，再启发式切出字符串和整数；
  • 物品名不在本地化文件里，它找到游戏原生语言其实是中文，中文原文全在一张“本地化 key 映射表”里；
  • 最后按“相关资源 → 物品 → 物品扩展信息（网格、图标）”这条链拼起来，生成了中文索引表。连“配套的资源编号 = 固定前缀 + 类型码 + 资源id”这种规律都是它自己看出来的。
Part 04

材质、Shader：直接跑游戏的原版 shader

到这一步它给了我两条路：A 是按材质参数自己重写 shader，B 是想办法直接跑游戏编译好的 shader。

我选了 B，后面证明这是对的。

  • 手机版 shader 是 Vulkan 的 SPIR-V 字节码，存在 shader 库里：库 → shader map 哈希 → 条目 → 组（Oodle 压缩的数据块）→ 切片，它一层层解开，再用 SPIRV-Cross 转成网页 WebGL2 能吃的 GLSL ES 3.0；
  • 没有用 three.js，直接写原生 WebGL2，因为要完全按游戏的方式喂数据；
  • 材质参数不是直接写进 shader 的，而是由一段“preshader”栈式字节码每帧算出来。它把引擎里解释这段字节码的函数从二进制里逆向出来，逐个操作码移植，然后在 CPU 模拟器里拿原生函数和自己的实现对跑：全部材质十一万多条 preshader，加上每个操作码随机三千组，逐位一致。
  • 对跑之前它按数据反推过一版操作码表，对跑后发现有好几个是错的（比如以为是“取反”的其实是“求长度”）；
  • WebGL2 不支持的东西一个个改：texture buffer 改成 2D 纹理、SSBO 改成定长数组、gather 改成 4 次取样、两个阶段同名但成员不同的 uniform 结构体要改名，等等；
  • 光照也是使用游戏自己的：手机延迟渲染，材质写 4 张 G-Buffer，然后跑游戏改过的全局光照 shader。这些 shader 有几百个排列，源码没有，排列的每一维是什么意思，它写脚本扫每个排列的反射特征，反推出来的。同时屏幕坐标、深度方向也照游戏的 Vulkan 约定。

第一天晚上，首套完整资源，几十组材质，全部用游戏自己的 shader 画了出来。

Part 05

骨骼、动画

和上次一样是 ACL 压缩：拉取源码、用本机的 MSVC 2019 编成原生库给解包库调。

  • 资源网格各自带一套骨骼子集，加上大量自己的附加骨骼，这些在游戏里是物理驱动的；
  • 顶点色的 alpha 里存了部位号，资源里写了要处理哪些逻辑，合起来写进整体材质的一个位掩码，shader 里把这些部位塌到原点。这是游戏本身的做法；
  • 后来我发现一些穿模。它查下来，游戏是用一个 ControlRig ，这是 UE 的一套字节码虚拟机，它就把这个虚拟机（包括懒求值分支）和用到的 25 个单元一起移植了，在模拟器里跑原生的整个 rig（21 万条指令）对比，逐位一致。
Part 06

物理

这一段是整个过程里最关键的转折。

我让它做某些资源的物理，它第一版是看着参数名自己写了一个 PBD 物理，看起来也能跑。我没接受，让它把游戏原生的代码逆向出来。

从这以后，项目里定了一条规矩，GPU 跑游戏自己的 shader，CPU 逻辑一律逆向移植，不按参数名手写近似，不能只凭感觉调整数值。

逆向的流程它自己总结成了固定的四步，后面所有系统都照这个来：

  1. 找入口：UE 的反射数据就是现成的索引。它解开安卓打包的重定位表，读出每个结构体所有属性的名字、类型、偏移，再从构造函数顺藤摸瓜找到虚表、找到被覆盖的虚函数；
  2. 反编译：213 MB 的库全量分析要好几个小时，它只做定向反编译。踩了几个坑：先要按 .eh_frame 把函数边界建好，否则尾调用会被并进来；栈检查失败和断言函数要标成不返回，否则每个函数都会“掉进”下一个函数；
  3. 写规格：结构体布局、每个函数、每帧算法，写成文档；
  4. 对照：在 unicorn 里直接跑原生函数，和移植版从同一个状态出发，逐个数组比。ARM 上快速倒数平方根的硬件近似会带来噪声，它专门做了一个“精确模式”，把这条指令换成精确值，这样就能区分是硬件噪声还是真 bug。

物理这一块，节点侧和求解器加起来将近六万条 ARM 指令。移植完“看起来对”，对跑一跑，查出来 20 多处真 bug。

它还普查了全游戏两千四百多个物理节点，把用到的几十种特性，全部移植并对跑通过。

再后来它又加了“变异测试”：故意在移植代码里改坏一处（比如把 < 改成 <=），看对跑能不能抓到，抓不到的要么证明是等价改动，要么补测试用例。

Part 07

动画蓝图

物理节点挂在每个资源自己的动画蓝图里，蓝图里还有一堆引擎的动画节点和蓝图逻辑。

  • 引擎的动画节点也是照游戏自己编译的版本逆向的，因为这个版本和原版 UE 有差异（对跑时确实抓到了两处行为不同）；
  • 游戏自研的节点一个个逆向；
  • 蓝图的 EventGraph 是 Kismet 字节码，它先在 Python 里写了一个虚拟机解出稳态值，后来干脆在浏览器里用 JS 实现了 Kismet 虚拟机，每帧跑真的蓝图逻辑。
Part 08

灯光、阴影、后期、时段天气

上次的灯光是换算参数，这次它把 CPU 算灯光参数的代码也逆向了，GPU 部分照样跑游戏的 shader。两层第一次在同一个系统里配合。

  • 级联阴影、聚光灯阴影：图集怎么分、矩阵怎么算，全部照原生，阴影深度用材质自己的阴影 shader 画；
  • 每个 draw 绑的 uniform 块，它都能逐字节转储出来，和模拟器里跑原生填充函数得到的结构体逐成员比，0 差异；
  • 后期链跑游戏的 shader。某些特性原本是计算着色器，WebGL2 没有，它改写成片元 pass，再用 Vulkan 直接在显卡上跑游戏原版 shader，152 个用例逐字一致；
  • 游戏有一套自己的动态时段天气系统，太阳、天光、后期、材质全局参数都由它每帧驱动。这套系统一半是 C++，一半是蓝图字节码，场景里还有关卡 Lua 脚本。

它把 C++ 部分逆向移植，蓝图字节码丢进自己的 Kismet 虚拟机跑，Lua 字节码自己写反汇编器读出来照着做。局部补光、天光、角色间接光、次表面散射的配置贴图，同样的流程一个个补上。

比如某个部件：以前一趟画完，有些角度会透出穿模；游戏其实是按材质里的“子过程”拆成好几趟，先抖动遮罩只写深度，再按深度相等画颜色，再画更近的位置，照做之后就对了。

Part 09

镜头动画、音频

游戏里的展示动画都是 LevelSequence。

  • 它把 UE 5.4 的序列求值（缓存插值、外插、循环、带权三次曲线、电影相机的 FOV 计算）逆向移植，再加上一个个轨道：淡入淡出、材质参数、粒子、蒙太奇混入、重新模拟等；
  • 序列里生成的角色也是蓝图，照样在 Kismet 虚拟机里跑；
  • 音频是 Wwise，从资源里解出事件、bnk、wem，转成 ogg，按序列的段落播放。
Part 10

粒子特效

上次是重写粒子模拟，这次不一样：UE 的 Niagara 粒子，CPU 部分是一段字节码（VectorVM）在虚拟机里跑。

  • 它把这个虚拟机移植成 JS，按 ARM 的浮点语义逐位解释（包括乘加融合这种细节），对跑逐位一致；
  • GPU 粒子是计算着色器，WebGL2 没有，它改用 WebGPU，把游戏的 SPIR-V 转成 WGSL 直接跑，八十多个 GPU 发射器全部接上；
  • 粒子的渲染还是用游戏粒子材质自己的 shader。
Part 11

大地图

最后是开放大地图的几何：

  • 大部分植被和建筑不是普通的网格组件，而是一套“GPU 驱动”的批量渲染，由计算着色器做剔除、LOD、实例压缩。它把这几个计算着色器的逻辑逐句移植到 CPU，再用 Vulkan 跑原版做对比；
  • 地形用的是虚拟纹理，页表、物理页、运行时虚拟纹理都照原生做，连 ASTC 贴图解码都挪到了 GPU 上；
  • 一开始大地图画面一片冲白，它查到真正的原因是测光遮罩没导出来，曝光退回了一个默认值。补上就好了，没有调任何数值。
Part 12

工程化

做到这里，代码量已经很大了，这一段我觉得值得说一下。

  • 项目里有一份给 AI 看的规则文件，写着铁律、命令、约定和进度，每次开新对话它先读这个；
  • 每个大任务开一个后台 agent，同时跑三四个。每个 agent 维护自己的检查点文档（步骤、地址、结论、踩的坑），额度断了我说一句“继续”，它就从检查点接着做；
  • 多个 agent 改不同的目录，共用的反编译工程用锁文件排队；
  • 为了改代码不改画面，它做了一个“确定性模式”：固定帧数、固定随机种子、固定粒子顺序，17 个场景逐像素截图，再加上每个子系统的 verify 接口（uniform 字节、渲染状态、和原生对比）。任何改动之后跑一遍，逐像素不同就要解释清楚；
  • 有一次它把 285 KB 的主文件拆成引擎模块（主文件剩 28 KB），又加了一个 Vue 的界面外壳，前后 17 个场景逐像素一致。
Part 13

其他

  • 景深：做完手机景深之后，近处有一圈阶梯。我让它查，它没有去加模糊，而是证明了阶梯来自游戏 shader 本身的 1/4 分辨率采样，真机上是靠每帧抖动的 TAA 加上景深专用的时间累积抹掉的，而我们还没有 TAA。最后的结论是：先默认关掉，等 TAA 移植完再开；
  • 批量导出时有 8 个场景失败，原因是游戏配置里引用的资源在包里根本不存在。它没有自己编一个兜底，而是去读 Lua 字节码和原生的异步加载代码，确认游戏遇到这种情况是“只跳过这一件，其它照常”，然后照这个逻辑改；
  • 性能优化也要求“画面一个像素都不能变”，它把每帧四百多次的缓冲上传降到了 0 次，然后跑回归证明逐像素一致。
